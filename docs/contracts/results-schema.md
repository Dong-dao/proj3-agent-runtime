## 1. 结果结构

`results.json` 顶层包含 `meta` 和 `runs`。

| 字段 | 含义 |
|---|---|
| `meta.os` | 实验环境的操作系统版本 |
| `meta.kernel` | 内核版本 |
| `meta.python` | Python 版本 |
| `meta.seed` | 随机种子，固定为 `20261111` |
| `meta.repeat` | 每组实验的重复次数，固定为 `3` |
| `runs` | 逐次运行的结果列表，每次运行保留一条记录 |
| `runs[].baseline` | 本次运行的模式，取 `serial`、`naive` 或 `runtime` |
| `runs[].load` | 本次运行使用的负载 |
| `runs[].repeat` | 本次运行是这一组的第几次重复 |
| `runs[].metrics` | 本次运行的指标，字段见第 2 节 |

## 2. 七项指标（S2 冻结，字段名/单位/采集点不可改）

| # | 指标 | 字段名 | 定义 | 采集点 | 单位 |
|---|---|---|---|---|---|
| 1 | 总完成时间 | `makespan_ms` | 最后一个任务终止时间减去首个任务开始时间 | 调度器时间戳 | 毫秒 |
| 2 | 上下文拷贝次数 | `copy_count` | 真实发生的对象复制事件数 | `ContextStore.write()` 写入复制分支 | 次 |
| 3 | 上下文拷贝字节数 | `copy_bytes` | 所有被复制对象的字节数之和 | `ContextStore.write()` 写入复制分支 | 字节 |
| 4 | 峰值内存 | `peak_rss_mb` | 实验期间采到的最大常驻内存 | 采样线程通过 `resource.getrusage` 获取 | MB |
| 5 | 调度开销 | `sched_overhead_pct` | 调度器自身耗时除以总完成时间，再乘以 100 | 调度器计时器 | 百分比 |
| 6 | 故障恢复时间 | `recovery_ms` | 从注入失败到受影响任务重新就绪的时间 | `fault.py` 日志 | 毫秒 |
| 7 | 受影响任务数 | `affected_tasks` | 因单个任务故障而未能按时完成的任务数 | 调度器统计 | 个 |

**七项不是六项**：`copy_count` 与 `copy_bytes` 是两项独立指标，任何文档出现「六项指标」一律按合并口径错误退回。

## 3. 采集与归档规则

- S1 用 stub 模拟数据跑通脚本、JSON 输出和绘图流程；S2 起接真实 runtime，采集七项真实值。
- `recovery_ms` 和 `affected_tasks` 在 S1 未采集，JSON 中用 `null` 表示「本轮未采集」；**不用 0**，避免与「采集到 0」混淆。S2 起写入真实数值。
- 第二条基线字段值统一为 `naive`，图例写 `naive (FIFO)`；旧文档里的 `fifo` 与本字段同指一条基线，S3 全量实验只写 `naive`。
- CLI 参数口径固定为 `--baseline serial,naive,runtime --repeat 3 --out results.json`。
- 每组三次重复的原始值都保存到 `results/`；重跑时另存，原始 JSON 不覆盖、不手改、只许追加。截图命令与输出同框、带日期归档。

## 4. 两个拷贝指标采集点：定名结论

草稿第 4 节有两处写法并存（`ContextStore.copy()` 与 `ContextStore.write()` 复制分支）。按 T2 已落地的 `runtime/context.py` 实现定死：

| 项 | 结论 |
|---|---|
| 采集方法 | `ContextStore.write()` 内的写入复制分支（S1 stub 在该分支留了「S2 COW 实现后启用」注释，S2 在此计数） |
| `copy_count` | 写入且 `refs > 1` 触发复制时 +1；原地独占写入（refs == 1）不计 |
| `copy_bytes` | 复制对象的字节长度累加，与 `copy_count` 同一分支、同一时刻记 |
| 为什么不是 `copy()` | 契约①第 4 节冻结的 `ContextStore` 接口没有独立 `copy()` 方法；计数落在 `write()` 复制分支才与签名和实现一致，不新增公开方法 |
| 共享命中率 | `share_hit_rate` 作为 `stats()` 附加诊断量保留，不属于七项指标，不进 `metrics` 字段表 |

## 5. S1 → S2 变更记录（新旧口径对照）

| 项 | 旧口径（S1 草稿） | 新口径（S2 冻结） | 原因 |
|---|---|---|---|
| 两个拷贝指标采集点 | `ContextStore.copy()`（指标核对清单）与 `write()` 复制分支（契约①）并存 | 统一为 `ContextStore.write()` 写入复制分支 | 契约①无 `copy()` 方法，按 T2 实现定名，消除歧义 |
| 故障指标未采集值 | 「置 0 或留空」（核对清单）/ `null`（草稿） | 统一 `null` | 0 与「采集到 0」混淆，null 明确表示未采集 |
| 第二基线命名 | `fifo`（本周规划）与 `naive`（技术栈 6.2）并存 | 字段值 `naive`，图例 `naive (FIFO)` | 两条基线同一实现，统一字段名避免 S3 图表打架 |
| 数据来源 | stub 模拟 | 真实 runtime（S2 接 COW / 故障 / 总线 / 可观测） | S2 目标为可运行代码与计数证据 |
| 七项指标定义 | 草稿文字 | 逐项定死定义/单位/采集点 | S3 复用前不得漂移 |
