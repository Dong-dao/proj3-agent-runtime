## 一、四大痛点 → 六大 OS 机制映射（主表，六行）

| # | 题面痛点 | OS 出处 | 我们的机制 | 状态不变量（一句话） | 可数证据 | 落点模块 | S1 是否实现 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | Agent 状态散乱、不可管 | 进程状态与 PCB | 六态生命周期状态机 + `transition()` 单一入口 | 状态唯一、终态不可回退、非法转换拒绝 | 迁移日志条数、非法转换拦截次数、终态回收数 | `agent.py` | ✓ S1 实现 |
| 2 | 依赖与优先级无法统一调度 | EEVDF 公平份额 + 时延约束（6.6 内核） | 依赖感知调度：DAG + eligible + 虚拟 deadline | 依赖未满足不入队、同一任务不重复派发 | 就绪队列长度、等待时间、总完成时间、deadline 违约数、调度开销 | `graph.py` `scheduler.py` | ✓ S1 实现 |
| 3 | 模型 / 工具 / 系统资源缺统一抽象 | 文件描述符表 + 权限位 | 统一 Resource Handle | 句柄不可伪造、越权必拒、终止必回收 | 申请 / 拒绝 / 回收计数（按 kind 分组） | `handle.py` `resource.py` | ✓ S1 实现（接口与配额账本） |
| 4 | 上下文 / KV Cache 冗余拷贝 | fork 写时复制 / 页表只读标记 | COW 上下文共享前缀 | 写入且 `refs > 1` 才复制、归零才释放 | 拷贝次数、拷贝字节数、峰值内存、共享命中率 | `context.py` | ✗ S2（S1 仅冻结签名 + stub） |
| 5 | 单体故障扩散、缺通信 | namespace / cgroup 隔离概念 | 故障域 + 进程内消息总线 | 故障不跨域、调度器始终可推进、消息不丢不重 | 故障恢复时间、受影响任务数、消息条数、控制指令延迟 | `fault.py` `bus.py` | ✗ S2 |
| 6 | 黑盒、无法干预 | /proc 与内核观测接口 | 可观测导出 + 控制指令 | 导出只读不改状态、控制指令只作用目标 Agent | 快照 JSON、暂停 / 恢复 / 终止指令日志 | `observer.py` | ✗ S2（S1 计数由各模块 stats() 提供） |

## 二、六项任务与 3+3 收窄落点

题面六项任务不必平均用力，按「3 核心做深 + 3 配套做通」收窄。六行映射与六项任务不是一一对应，答辩时要能说清每项任务落在哪行：

| 题面任务 | 落在映射表 | 深度 |
| --- | --- | --- |
| ① 多 Agent 调度（依赖、动态生成、资源感知） | 第 2 行 | 核心，做深 |
| ② 统一执行抽象（生命周期、状态转换、OS 资源关系） | 第 1、3 行 | 核心，做深 |
| ③ 上下文管理（复用、压缩、隔离） | 第 4 行 | 核心，做深（S2） |
| ④ 容错（隔离单体故障、避免级联） | 第 5 行 | 配套，做通（S2） |
| ⑤ 复杂多 Agent 场景验证 | 三基线实验整体 | 配套，做通（S3） |
| ⑥ Agent 间高效通信 | 第 5、6 行 | 配套，做通（S2） |

不做项与边界在《范围说明》主动交代：真实 LLM / KV Cache、改内核 / eBPF / cgroup 编程、Docker / K8s、多机分布式、图形化 IDE。

## 三、用户态边界声明（防守节，原样进设计文档）

评委最容易追问「你们这不就是在 Python 里模拟了一下吗」。主动写清边界比假装改了内核更拿分：

| 作品里的机制 | OS 原型 | 实现形态 | 必须如实声明的边界 |
| --- | --- | --- | --- |
| Agent 状态机 | PCB 与五态模型 | 真实用户态状态机对象，六态 + 矩阵 + 日志 | 不参与内核调度，不产生真实上下文切换 |
| 依赖感知调度 | EEVDF、cgroup 配额 | 真实事件循环，决定就绪任务执行顺序 | 迁移「公平份额 + 时延约束」思想，非移植内核调度类；配额是逻辑账本 |
| COW 上下文 | 页表级写时复制 | 不可变前缀 + 引用计数 + 写入构造新对象 | **逻辑 COW，不是页表级；不接 KV Cache，不省显存**，省的是对象拷贝 |
| 统一 Resource Handle | fd 与权限表 | 用户态句柄对象，统一申请、越权拒绝、终止回收 | 不是内核 fd，不跨进程传递 |
| 隔离域 | 地址空间、namespace | 域标签 + 访问控制 + 超时熔断 | 不是硬件页表隔离，是进程内逻辑隔离 |
| 消息总线 | 共享内存、消息队列 | 进程内消息总线 + 共享上下文区 | 不是内核 IPC，不做跨机与序列化 |
| /proc 式导出 | procfs、cgroup 统计 | JSON 快照 + CLI 控制指令 | 不是真挂 procfs，是同构只读状态视图 |

## 四、版本校正（必须写进文档，避免概念陈旧）

题面参考资料点名 Linux CFS，但目标平台 openEuler 24.03 LTS SP3 基于 Linux 6.6 内核，**6.6 起已引入 EEVDF 调度器**。我们迁移的是「公平份额 + 时延约束」这条思想主线，不是照抄 vruntime 表述；把虚拟 deadline 引入依赖 DAG 调度，反而更贴近当前内核演进，是明确的设计创新点。（详见《设计草稿三件事》第二件）
