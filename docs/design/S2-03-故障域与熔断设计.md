> 对应 S2 逐日：11/27 故障域与熔断。

## 1. 题面痛点与 OS 出处

**痛点**：一个 Agent 超时或异常退出，若故障扩散到调度器与消息总线，整个多 Agent 系统会停摆。

**OS 出处**：namespace / cgroup 的故障隔离边界——一个容器的资源耗尽不应拖垮宿主与其他容器；内核 panic 与进程崩溃的隔离层级。我们迁移「故障域」这个概念：把可能失败的执行体圈在域内，域外的控制面保持存活。

## 2. 故障域边界（关键设计决策）

| 组件 | 在域内/外 | 理由 |
|---|---|---|
| 各 Agent 执行体 | **域内** | 可能超时、抛异常，是故障源 |
| 调度器 `scheduler.py` | **域外** | 必须始终可推进，是控制面 |
| 消息总线 `bus.py` | **域外** | 故障后系统仍需通信 |
| 可观测 `observer.py` | **域外** | 故障时要能导出现场 |
| 资源管理 `resource.py` | **域外** | 故障后要能回收句柄 |

**一句话**：以 Agent 执行域为界，调度器与总线在域外。这是答辩必答项——故障域不能画成「整个系统」，否则等于没有隔离。

## 3. 超时熔断流程

```text
Agent 执行超时 / 抛异常
  → FaultDomain 记故障时刻
  → Scheduler.on_fail(task_id, reason) 走 RUNNING → FAILED 单一入口
  → 依赖它的任务：按策略降级或重新就绪（不直接置 FAILED）
  → 其余就绪任务继续派发
  → 受影响任务重新就绪时刻 − 故障时刻 = recovery_ms
  → 未能按时完成的任务数 = affected_tasks
```

**不变量**：故障不跨执行域；调度器在任一单体失败后仍能 `next()` 推进。

## 4. 状态不变量

| 编号 | 不变量 | 由哪段代码保证 | 怎么测 |
|---|---|---|---|
| F1 | 故障只影响域内 Agent | `FaultDomain.register` 登记成员，熔断只作用于成员 | 注入 A 失败，断言 B 状态不变、继续 RUNNING |
| F2 | 失败走单一入口 | `Scheduler.on_fail` → `transition(RUNNING→FAILED)` | 断言有 FAILED 迁移日志，无直接状态赋值 |
| F3 | 调度器故障后仍推进 | `on_fail` 只标记失败、不中断事件循环 | 注入失败后调用 `next()`，断言返回下一个就绪任务 |
| F4 | 回收计数完整 | 进入 FAILED 触发 `release_all` | 断言该 agent 句柄表归零 |
| F5 | 恢复时间可采 | 故障与重新就绪各打时间戳 | 注入后断言 `recovery_ms` 非 null |

## 5. 可数证据（对接七项指标）

| 证据 | 指标字段 | 采集位置 | S2 验收期望 |
|---|---|---|---|
| 故障恢复时间 | `recovery_ms` | `fault.py` 日志时间戳 | 注入后非 null、为合理正数 |
| 受影响任务数 | `affected_tasks` | 调度器统计 | 与注入用例预期一致 |
| 其余任务继续 | 调度器推进日志 | `scheduler.next()` | 单 Agent 失败后仍有后续派发 |

**定义提醒**：`affected_tasks` 是「未能按时完成」的任务数，不是「被杀死/重启」的任务数——故障注入实验里这两个数不同，别混。

## 6. 与 T2 实现的对接点

T2 已落地 `runtime/fault.py`：`FaultDomain`（`register` / `stats`），`stats()` 返回 `recovery_ms / affected_tasks / members`（S1 均为 None）；`Scheduler.on_fail(task_id, reason)` 已在契约①第 5 节与 T2 11/24 提交中落地。S2 实现：①补超时检测与熔断开关；②在 `on_fail` 里写两个指标时间戳与计数。**不改签名**。

## 7. 用户态边界声明

| 作品里的机制 | OS 原型 | 必须如实声明的边界 |
|---|---|---|
| 故障域 + 熔断 | namespace / cgroup 隔离 | 进程内逻辑隔离，不是内核级资源隔离；熔断是用户态逻辑判定 |
