## 一、七项指标口径基准（先抄到一张表，核对时逐行对）

| # | 指标 | 字段名（6.2 节 JSON） | 定义 | 采集点 | 单位 |
| --- | --- | --- | --- | --- | --- |
| 1 | 总完成时间 | `makespan_ms` | 首个任务开始到最后一个任务终止 | 调度器时间戳 | 毫秒 |
| 2 | 上下文拷贝次数 | `copy_count` | 真实对象复制事件数 | `ContextStore.copy()` | 次 |

## 二、核对步骤（拿到栾诗童的字段表后逐条做）

1. **对表头**：她的表是不是 7 行？出现「六项指标」字样就是合并口径（拷贝次数/字节数被并成一项），标红退回。
2. **对字段名**：七个 `metrics` 字段名与上表逐字一致，缺一个标一个。
3. **对单位**：毫秒 / 次 / 字节 / MB / 百分比 / 毫秒 / 个，写错单位标红（尤其调度开销是百分比不是毫秒）。
4. **对采集点**：每个指标是否写明落到哪段代码（调度器时间戳、`ContextStore.copy()`、采样线程、调度器计时器、`fault.py`、调度器统计）。只写「记录」没写位置的不算数。
5. **对 CLI**：`--baseline` 枚举、`--repeat`、`--out` 三个参数与 6.2 节一致；`meta` 五字段齐全。
6. **对原始数据规则**：字段表里有没有写明「原始 JSON 不许覆盖、不许手改、三次重复的原始值都在」？没有就补上，这是红线。
7. **S1 特例**：`recovery_ms` 与 `affected_tasks` 在 S1 还没有 `fault.py`，字段表要注明「S2 起采集，S1 置 0 或留空并在文档说明」，别让陈苗苗 S1 无从下手。

**问题**：naive 与 fifo 是不是同一个基线的两个名字？S1 对比图叫 fifo、S3 全量叫 naive，到了 S3 图表和文档里两个名字会打架，答辩也会被问。**处理建议**：S1 的 fifo 就是 naive 基线（朴素调度 = 无依赖感知的 FIFO 实现），文档统一叫 **naive**，图例标注「naive (FIFO)」；或反过来统一叫 fifo。定名后同步改《本周规划》与栾诗童脚本，并记入契约②更新记录。定名前先跟栾诗童、陈苗苗在群里说一句。

## 四、易错点提醒（给栾诗童的核对意见里重点写这几条）

1. 「六项」还是「七项」：拷贝次数与拷贝字节数是**两项独立指标**，历史文档里有写成六项的坑，字段表出现六行直接退回。
2. `makespan_ms` 起点是「首个任务开始」不是「进程启动」——stub 数据里这两个值不一样，别用错。
3. 调度开销是百分比、除数是总完成时间；写成绝对毫秒是错口径。
4. 受影响任务数定义是「**未能按时完成**」的任务数，不是「被重启/被杀死」的任务数——故障注入实验里这两个数不一样。
5. seed 固定 `20261111`、repeat 3，任何一次「为了图好看」改 seed 或挑重复次数都要在新旧口径对照里说明，否则算违规。
6. 原始 JSON 是证据链：只许追加不许覆盖，截图要带日期归档；AI 台账如实记录 plot/bench 脚本的生成与修改比例。
