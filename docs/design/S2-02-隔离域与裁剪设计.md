# S2 机制设计说明 ②：隔离域、访问控制与上下文裁剪

> 交付人：董博文（T1 机制设计）　日期：2026-11-25　落盘路径：`docs/design/S2-02-隔离域与裁剪设计.md`
> 对应 S2 逐日：11/26 隔离域与裁剪策略。

---

## 1. 题面痛点与 OS 出处

**痛点**：多 Agent 共享上下文区时，一个 Agent 可能读到不属于自己的上下文；同时上下文随任务增长会无限膨胀。

**OS 出处**：
- 隔离域 ← namespace / 地址空间隔离：每个进程只看见自己的地址空间，跨域访问被拒。
- 裁剪 ← 内存回收与紧凑：对象不再无限增长，按策略截断保留。

## 2. 隔离域机制定义

- **域标签**：每个上下文对象带 `domain_tag`，每个 Agent 属于一个域。对象结构里已有 `domain_tag` 与 `holders` 两个字段（T2 `runtime/context.py` 已落地），S2 直接启用，不新增结构。
- **访问控制**：`read(agent_id, ctx_id)` / `write(...)` 先校验 `agent_id in holders`；不在持有者集合即越权，抛 `E_PERM` 并记一条 WARNING 日志。
- **域边界**：以 Agent 为最小隔离单位；共享前缀是「显式 acquire 后的共享」，不是「默认全域可读」——共享必须登记，未登记即隔离。

## 3. 裁剪策略定义

- 上下文超过阈值时按**定长裁剪**（保留最近 N 条 / 前缀保留），不做语义压缩、不引入推理框架。
- 定长裁剪的理由：可复现、可计数、无外部依赖；语义摘要会引入不确定性与模型依赖，违反技术栈红线（不接真实大模型）。
- 裁剪触发点与计数：`ContextStore` 内按字节长度判定，裁剪前后长度记日志，供实验侧统计上下文长度与命中率。

## 4. 状态不变量

| 编号 | 不变量 | 由哪段代码保证 | 怎么测 |
|---|---|---|---|
| D1 | 非持有者不得读写 | `read`/`write` 的 `holders` 校验 | 用域 B 的 agent_id 读域 A 的 ctx_id，断言抛 `E_PERM` |
| D2 | 越权必留日志 | 校验失败分支的 `log.warning` | 断言日志含 `E_PERM` 与双方 ID |
| D3 | 裁剪后上下文不超过阈值 | 裁剪分支 | 注入超长上下文，断言裁剪后长度 ≤ 阈值 |
| D4 | 裁剪不破坏引用关系 | 裁剪只改 `bytes`、不改 `holders`/`refs` | 裁剪后断言 `refs == len(holders)` 仍成立 |

## 5. 可数证据

| 证据 | 采集位置 | S2 验收期望 |
|---|---|---|
| 越权拒绝次数 | `E_PERM` 日志计数 | 越权用例触发后 > 0 |
| 上下文长度 | 裁剪日志 / `context.stats()` | 裁剪后 ≤ 阈值 |
| 共享命中率 | `ContextStore.stats().share_hit_rate` | 合法共享时 > 0 |

## 6. 与 T2 实现的对接点

T2 `runtime/context.py` 的 `read()` / `write()` 已有 `holders` 校验骨架和 `E_PERM` 日志（S1 单域下已可触发），`domain_tag` 字段已就位。S2 只需：①把校验从「holders 集合」扩展为「域标签 + holders 双重判定」；②在 `write()` 里补定长裁剪分支。**不改契约①签名**，错误码沿用 `handle.E_PERM`。

## 7. 用户态边界声明

| 作品里的机制 | OS 原型 | 必须如实声明的边界 |
|---|---|---|
| 隔离域 | 地址空间、namespace | **不是硬件页表隔离**，是进程内逻辑隔离（域标签 + 访问控制） |
| 上下文裁剪 | 内存回收/紧凑 | 定长裁剪，非语义压缩；不接模型、不保证语义完整性 |
